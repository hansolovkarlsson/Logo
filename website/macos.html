Download, or build from source

LogoMotive on macOS

macOS is where LogoMotive is developed and used daily — it's the original target, not a port. There are two ways to get it running: download a pre-built binary, or build it yourself in about a minute. This page covers both.

The short version

On Apple Silicon: install Homebrew if needed, install the two libraries, then grab and unzip the latest archive from the Releases page and run it.

brew install gtk4 sdl2
unzip ~/Downloads/logomotive-*-macos-arm64.zip -d ~/Downloads/logomotive
cd ~/Downloads/logomotive/logomotive-*-macos-arm64
./logomotive

No Homebrew yet, an Intel Mac, or you'd rather build it yourself? Keep reading.

1

What you need

Either way, the app links against two libraries at runtime:

  • GTK4 — the windowing toolkit. This is the big one.
  • SDL2 — sound and joystick input. Not optional, even if you never make a sound: the interpreter links against it unconditionally.
  • Homebrew — the only supported way to get both on macOS.

Building from source adds two more, both usually already on your Mac:

  • Xcode's Command Line Tools — supplies the C compiler and make. Homebrew itself requires these to install, so a Mac with Homebrew already has them.
  • pkg-config — how the Makefile finds GTK4 and SDL2. Installed alongside them in step 4.
2

Download or build?

Both produce the same app. Pick whichever fits:

  • Download if you're on Apple Silicon (M1 or later) and just want to run it — skips the compiler entirely. That's the only architecture a release is built for.
  • Build from source if you're on an Intel Mac (no pre-built binary exists), you want the latest unreleased code, or you're planning to change something.

Building isn't the fallback option here the way it is on Linux — it's genuinely just as quick, since Homebrew is doing the same library install either way. The only extra step is compiling, and that's under a second on a modern Mac.

3

Download a release

Grab the …-macos-arm64.zip archive from the Releases page and unzip it — the filename carries the version, e.g. logomotive-v0.1.0-macos-arm64.zip. Inside: the logomotive executable, the examples/ folder, and a README.txt with these same notes.

The archive doesn't bundle GTK4 or SDL2 — install them once with Homebrew:

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
brew install gtk4 sdl2

(Skip the first line if brew --version already prints something.)

Then, from a terminal in the unzipped folder:

./logomotive
./logomotive examples/concurrent_agents.logo

Gatekeeper will warn on first launch. This build isn't code-signed or notarized, so macOS reports it as from an unidentified developer. Right-click logomotive in Finder and choose Open (only needed once), or allow it afterwards under System Settings → Privacy & Security. This is expected, not a sign anything's wrong — see the roadmap for the notarization plan.

4

Build from source

git clone https://github.com/hansolovkarlsson/LogoMotive.git
cd LogoMotive
./scripts/install_brew.sh   # only if `brew --version` doesn't already work
./scripts/install_gtk.sh
make run

install_gtk.sh runs brew install gtk4 sdl2 pkg-config and then checks that a compiler and make are really present, rather than assuming — so a missing Xcode Command Line Tools install is reported immediately, with the exact command to fix it, instead of failing three steps later mid-compile.

Or do each piece by hand:

xcode-select --install
brew install gtk4 sdl2 pkg-config
make
make test

make alone produces bin/logomotive; make test builds and runs all eight headless test binaries, which should each end with:

All tests passed.

There's also ./build.sh, a single-shot alternative that compiles everything in one invocation without make.

5

Run it

From a source build:

make run
./bin/logomotive
./bin/logomotive examples/sample.logo

A window opens: turtle canvas on one side, history pane and entry box on the other. Type REPEAT 4 [FD 100 RT 90] into the entry box and press Return.

There are 71 scripts in examples/ covering most of the language. For scripting or automation, --headless runs with no window at all — PRINT goes to stdout and the process exits when the script ends:

./bin/logomotive --headless examples/lists.logo

./bin/logomotive --help lists every option.

6

Menus and shortcuts

Unlike Linux and Windows, the menu bar lives in the system-wide bar at the top of the screen, not inside the window — the standard macOS layout. File has Editor, Open, Save, Export as PNG, Load/Save Bytecode and Quit; View has the text-size actions and the Show Input Window toggle.

File > Editor… opens a separate window for writing a whole program — several TO/END definitions plus top-level setup — instead of the entry box's one-line-at-a-time submission, with its own Open/Save (the raw file, not just the current definitions) and a Run button. It stays open (hidden, not closed) in the background, so text survives switching back to the main window.

Shortcuts use Cmd, not Ctrl:

  • Cmd+Shift+E open the Editor window · Cmd+Return inside it runs the whole buffer
  • Cmd+O open a .logo file · Cmd+S save
  • Cmd+E export the canvas as a PNG
  • Cmd+Shift+O / Cmd+Shift+S load and save bytecode
  • Cmd+Plus / Cmd+Minus / Cmd+0 text size
  • Cmd+Shift+I hide the input pane, leaving just the canvas
  • Cmd+Q quit

Ctrl+C is different. Typed in the terminal you launched from, it interrupts the running script and prints Interrupted. — it doesn't close the app, which keeps running and stays ready for the next command. That's the only way to stop a runaway loop short of quitting.

Troubleshooting

"logomotive" cannot be opened because the developer cannot be verified

Gatekeeper, on an unsigned build — see step 3. Right-click the binary and choose Open once, or allow it under System Settings → Privacy & Security.

dyld: Library not loaded: …libgtk-4… or similarly for libSDL2

GTK4 or SDL2 isn't installed. Run brew install gtk4 sdl2 — both are required, and a machine with only one installed fails exactly this way rather than starting.

Package gtk4 was not found in the pkg-config search path, while building

Usually Homebrew isn't on your shell's PATH. On Apple Silicon, Homebrew installs to /opt/homebrew; on an Intel Mac, /usr/local. The Homebrew installer prints the exact line to add to your shell profile at the end of the install — run it again if you skipped past it, or open a new terminal window, which picks it up automatically on a fresh install.

xcrun: error: invalid active developer path, or make: command not found

Xcode's Command Line Tools aren't installed:

xcode-select --install

The app won't close from the terminal

Its interrupt handler survives SIGTERM, so a plain kill — and timeout — won't stop it. Quit normally with Cmd+Q, or:

pkill -x -9 logomotive

Don't use pkill -f bin/logomotive: that pattern matches the shell you typed it into and kills your own terminal.

8

What's actually been tested

Stated precisely, so you know what you're relying on:

  • Apple Silicon (arm64) — the original development platform, built and run here every day. This is also the only architecture the Releases page publishes a binary for.
  • Intel Macs (x86-64) — expected to work by building from source (the Makefile and dependency scripts have no architecture-specific code, and Homebrew's Intel prefix is handled the same way as its Apple Silicon one), but not separately verified, and no pre-built download is offered for it.

If you build or run it somewhere not on this list, say so on the issue tracker — working or not, that's useful.

Built alongside LogoMotive's own C interpreter — see the repository for the source, the language design docs, and the full changelog.

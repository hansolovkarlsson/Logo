Download, prepare, build

LogoMotive on Linux

There's no Linux binary to download yet — you build it from source, which is three commands and usually under a minute. Everything on this page has been run on a real machine, not transcribed from documentation.

The short version

git clone https://github.com/hansolovkarlsson/LogoMotive.git
cd LogoMotive
./scripts/install_gtk.sh
make run

If that worked, you can stop reading. The rest of this page is for when it didn't, or when you'd rather install things yourself.

1

What you need

LogoMotive is a C program with two runtime libraries. You need all of these before it will build:

  • GTK4 — the windowing toolkit. This is the big one.
  • SDL2 — used for sound and joystick input. Not optional, even if you never make a sound: the interpreter links against it unconditionally.
  • pkg-config — how the Makefile finds the other two.
  • A C compiler and make — gcc and clang both work.

You don't have to install these individually. scripts/install_gtk.sh in step 3 installs all four on Linux, and checks afterwards that the compiler and make really are present rather than assuming it — so if something is still missing you're told immediately, not three commands later in the middle of a compile.

2

Get the source

git clone https://github.com/hansolovkarlsson/LogoMotive.git
cd LogoMotive

No git? The GitHub page has a Download ZIP button under Code, which works just as well — unzip it and cd into the folder. Every command on this page is run from the project root, the directory holding Makefile.

3

Install the dependencies

The bundled script detects your package manager and installs everything from step 1:

./scripts/install_gtk.sh

It probes for brew, dnf, apt-get and pacman, in that order, and uses the first one it finds. It will ask for your password, because installing packages needs root. On macOS it installs the libraries only — the compiler there comes from Xcode's Command Line Tools, and it'll tell you so if they're absent.

Or do it by hand. These are complete on a fresh machine:

Fedora, RHEL, and relatives

sudo dnf install gtk4-devel SDL2-devel pkgconf-pkg-config gcc make

Ubuntu, Debian, Mint, and relatives

sudo apt-get install libgtk-4-dev libsdl2-dev pkg-config build-essential

Arch and relatives

sudo pacman -S --needed gtk4 sdl2 pkgconf base-devel

The Fedora and Ubuntu package names above are known-good — both were used to build and test LogoMotive on 2026-08-13. The Arch names come from Arch's own package index and have not been through a real build. If you're on Arch and they're wrong, that's a bug worth reporting.

Want to check what you've got before building? These print a version number if the library is installed and fail if it isn't:

pkg-config --modversion gtk4
pkg-config --modversion sdl2
4

Build and test

make

That produces bin/logomotive. You'll see a number of -Wformat-truncation warnings scroll past — those are known and harmless. What matters is that it finishes without an error.

To confirm the build is actually sound rather than merely complete, run the test suites:

make test

Eight test binaries build and run. All eight should end the same way:

All tests passed.

These are headless — no window opens and none is needed. If all eight pass, the interpreter, parser, evaluator, bytecode compiler and VM are all working correctly on your machine.

There's also ./build.sh, a single-shot alternative that compiles everything in one gcc invocation without make. Use it if make is unavailable; otherwise prefer make, which only rebuilds what changed.

5

Run it

make run

Builds if needed, then opens the window: turtle canvas on one side, history pane and entry box on the other. Type REPEAT 4 [FD 100 RT 90] into the entry box and press Enter.

Once built, you can also run the binary directly, optionally handing it a script to load and run at startup:

./bin/logomotive
./bin/logomotive examples/sample.logo

There are 71 scripts in examples/ covering most of the language. And for scripting or automation, there's a mode with no window at all — PRINT goes to stdout and the process exits when the script ends:

./bin/logomotive --headless examples/lists.logo

./bin/logomotive --help lists every option.

6

Menus and shortcuts on Linux

Two differences from the macOS build, both deliberate:

The menu bar is inside the window, near the top, rather than in a system-wide bar at the top of the screen. File has Editor, Open, Save, Export as PNG, Load/Save Bytecode and Quit; View has the text-size actions and the Show Input Window toggle.

File > Editor… opens a separate window for writing a whole program — several TO/END definitions plus top-level setup — instead of the entry box's one-line-at-a-time submission, with its own Open/Save (the raw file, not just the current definitions) and a Run button. It stays open (hidden, not closed) in the background, so text survives switching back to the main window.

The modifier key is Ctrl, where macOS uses Cmd:

  • Ctrl+Shift+E open the Editor window · Ctrl+Return inside it runs the whole buffer
  • Ctrl+O open a .logo file · Ctrl+S save
  • Ctrl+E export the canvas as a PNG
  • Ctrl+Shift+O / Ctrl+Shift+S load and save bytecode
  • Ctrl+Plus / Ctrl+Minus / Ctrl+0 text size
  • Ctrl+Shift+I hide the input pane, leaving just the canvas
  • Ctrl+Q quit

Ctrl+C is different. Typed in the terminal you launched from, it interrupts the running script and prints Interrupted. — it doesn't close the app, which keeps running and stays ready for the next command. That's the only way to stop a runaway loop short of quitting.

7

Troubleshooting

Package gtk4 was not found in the pkg-config search path

GTK4's development files are missing. Having GTK4 itself installed isn't enough — you need the -devel / -dev package, which is what step 3 installs. The same message naming sdl2 means the same thing for SDL2.

make: gcc: No such file or directory

No compiler. Run ./scripts/install_gtk.sh, which installs one on Linux — or install your distribution's build-tools package by hand, as in step 3.

Errors mentioning open_memstream, usleep or clock_gettime, or a linker error about atan2

You're building an old checkout. Both were fixed on 2026-08-13 (a strict-C11 mode hiding glibc functions, and a missing -lm). Pull the latest main.

The window doesn't appear, or renders oddly

LogoMotive has been tested under both Wayland and X11. If your session is Wayland and something looks wrong, force the X11 backend to compare:

GDK_BACKEND=x11 ./bin/logomotive

No File or View menu at all

That was a real bug, fixed on 2026-08-13 — GTK4 changed a default that macOS never depended on, so the menu bar silently never rendered on Linux. If you see it on a current checkout, it's new: please report it, noting your GTK version from pkg-config --modversion gtk4.

The app won't close from the terminal

Its interrupt handler survives SIGTERM, so a plain kill — and timeout — won't stop it. Use Ctrl+Q in the window, or:

pkill -x -9 logomotive

Don't use pkill -f bin/logomotive: that pattern matches the shell you typed it into and kills your own terminal.

8

What's actually been tested

Stated precisely, so you know what you're relying on:

  • Fedora 42 (aarch64), GTK 4.18.6 — verified 2026-08-13. Clean build, all 8 suites, GUI under both Wayland and X11, menus and shortcuts exercised by hand.
  • Ubuntu 24.04.4 LTS (aarch64), GTK 4.14.5 — verified 2026-08-13. Clean build, all 8 suites, build.sh and headless mode working, menu bar confirmed present, Ctrl+O and Ctrl+S confirmed working by hand.
  • Mint, Pop!_OS and other Ubuntu derivatives — expected to work, not separately tested. They're built on the Ubuntu base and install the same packages.
  • Arch, Debian proper, x86_64 anything — untested. Nothing is known to be wrong; nobody has run it. Both verified machines above were ARM.

If you build it somewhere not on this list, say so on the issue tracker — working or not, that's useful.

Why no download? A Linux binary can't simply be handed out the way the macOS one is: it links against glibc, GTK4 and SDL2, and glibc's versioning means a binary built on a newer distribution won't start on an older one. Doing it properly means a Flatpak, which is on the roadmap but not built yet. Until then, from source is the honest answer — and it does compile in well under a minute.

Built alongside LogoMotive's own C interpreter — see the repository for the source, the language design docs, and the full changelog.
